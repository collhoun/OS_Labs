# Лабораторная работа №4. Вариант 14

Работа с процессами и обмен данными через отображаемые файлы
(memory-mapped files) в Linux.

## Задание

Используется вариант 14 из лабораторной работы №2.

Родительская программа создаёт два дочерних процесса:

1. Child1 переводит строку в нижний регистр.
2. Child2 заменяет последовательности обычных пробелов одним пробелом.
3. Родитель выводит полученный результат.

Родитель принимает строки произвольной длины до конца ввода.

Пример:

```text
Ввод:     HeLLo    WORLD
Результат: hello world
```

В лабораторной №4 обмен строками реализован через отображаемый файл.
Для синхронизации используются межпроцессные семафоры.

## Требования

- Linux.
- GCC с поддержкой C11.
- GNU Make.
- Bash для запуска цели `make test`.
- Поддержка POSIX mmap и межпроцессных неименованных семафоров.

## Файлы проекта

| Файл | Назначение |
|---|---|
| common.h | Общая структура данных и вспомогательные функции |

| child1.c | Запуск обработчика перевода в нижний регистр |

## Сборка

Из каталога проекта:

```bash
make
```

Будут созданы исполняемые файлы:

```text
parent
child1
child2
```

Для полной пересборки:

```bash
make clean
make
```

## Запуск

Запускать программу нужно из каталога, в котором находятся
все три исполняемых файла:

```bash
./parent
```

Или:

```bash
make run
```

Родитель запускает детей по относительным путям
`./child1` и `./child2`.

Введите строки, например:

```text
HeLLo    WORLD
ABC   DEF     GHI
```

Результат:

```text
hello world
abc def ghi
```

Для завершения ввода нажмите Ctrl+D на пустой строке.

В интерактивном терминале введённый текст также отображается
самим терминалом. Это не дополнительный вывод программы.

## Ввод из конвейера или файла

```bash
printf 'HeLLo    WORLD\nABC   DEF\n' | ./parent
```

Чтение из файла:

```bash
./parent < input.txt
```

Сохранение результата:

```bash
./parent < input.txt > output.txt
```

Приглашение к вводу и сообщения об ошибках направляются в stderr.
Обработанные строки направляются в stdout.

## Проверка

```bash
make test
```

Проверка сравнивает фактический вывод с ожидаемым.
Она охватывает:

- перевод английских букв в нижний регистр;
- сжатие повторяющихся пробелов;
- несколько строк подряд;
- пустую строку;
- строку из пробелов;
- последнюю строку без завершающего перевода строки.

При совпадении выводится:

```text
Test passed
```

Эта проверка не заменяет отдельную проверку длинных строк
и аварийных ситуаций.

## Организация процессов

Оба дочерних процесса создаются родителем:

```text
parent
├── child1
└── child2
```

Обработка выполняется последовательно:

```text
parent → child1 → child2 → parent
```

Одновременно обрабатывается одна строка.

## Организация общего файла

Родитель создаёт временный файл через `mkstemp()`:

```text
/tmp/lab4-XXXXXX
```

Символы X заменяются уникальной последовательностью.

Общий файл содержит:

```text
┌───────────────────────────────────┐
│ Служебный заголовок Shared         │
│ - семафоры                        │
│ - длина строки                    │
│ - флаг завершения                 │
├───────────────────────────────────┤
│ Выравнивание до границы страницы   │
├───────────────────────────────────┤
│ Строка с завершающим '\0'          │
└───────────────────────────────────┘
```

Заголовок и строка отображаются отдельно через `mmap()`
с флагом `MAP_SHARED`.

Заголовок остаётся отображённым во время работы процесса.
Область строки отображается только на время доступа к ней.

Размер файла изменяется через `ftruncate()`, когда оба
дочерних процесса не обращаются к области строки.

## Синхронизация

В заголовке расположены четыре семафора:

| Семафор | Назначение |
|---|---|
| run[0] | Разрешение на обработку для child1 |
| done[0] | Подтверждение завершения child1 |
| run[1] | Разрешение на обработку для child2 |
| done[1] | Подтверждение завершения child2 |

Все семафоры создаются с начальным значением 0.

Последовательность обработки:

1. Родитель записывает строку в отображаемый файл.
2. Родитель увеличивает `run[0]`.
3. Child1 просыпается и переводит строку в нижний регистр.
4. Child1 увеличивает `done[0]`.
5. Родитель получает подтверждение и увеличивает `run[1]`.
6. Child2 просыпается и сжимает пробелы.
7. Child2 обновляет длину строки и увеличивает `done[1]`.
8. Родитель получает подтверждение и выводит результат.

Семафоры предотвращают одновременное изменение строки
разными процессами и согласуют доступ к общей памяти.

Каналы pipe для передачи данных не используются.

| Функция | Назначение |
|---|---|
| mkstemp | Создать уникальный временный файл |
| ftruncate | Установить размер файла |
| mmap | Отобразить файл в память |
| munmap | Снять отображение |
| fork | Создать дочерний процесс |
| execl | Запустить дочернюю программу |
| sem_init | Инициализировать семафор |
| sem_wait | Ожидать разрешение |
| sem_post | Передать разрешение |
| sem_timedwait | Ожидать подтверждение с ограничением времени одного ожидания |
| waitpid | Получить статус дочернего процесса |
| unlink | Удалить имя временного файла |

## Завершение

При достижении конца ввода родитель:

1. Устанавливает `stop = 1`.
2. Будит обоих детей.
3. Дожидается их завершения через `waitpid()`.
4. Уничтожает семафоры.
5. Снимает отображение заголовка.
6. Закрывает и удаляет временный файл.

При обнаруженной ошибке родитель останавливает оставшихся
детей и освобождает ресурсы.

Во время ожидания результата родитель периодически проверяет,
не завершился ли один из детей.

## Особенности и ограничения

- Преобразование регистра рассчитано на английские буквы.
  Кириллица в UTF-8 требует отдельной реализации.
- Сжимаются только обычные пробелы `' '`.
  Табуляции не изменяются.
- Последовательность пробелов в начале или конце строки
  превращается в один пробел.
- Переводы строк сохраняются.
- Ввод рассматривается как текст без встроенных нулевых байтов.
- Длина строки ограничена доступными ресурсами сервера,
  а не фиксированным массивом.
- Используются семафоры, а не сигналы для уведомлений.
- При принудительном завершении, например SIGKILL,
  временный файл может остаться в `/tmp`.
- Если ребёнок остаётся живым, но зависает, программа
  не устанавливает общий предельный срок обработки.
- Автоматическая проверка подтверждает базовые преобразования,
  но не доказывает корректность всех аварийных сценариев.
